## 一、CLI 可用管控途径（本轮实测的实质结论）

对 `multica` CLI 的实际命令面做了枚举（`multica --help`、`multica attachment --help`、`multica issue comment --help`）：

| 命令 | 存在 | 语义（来自 CLI 自带帮助） |
|---|---|---|
| `multica attachment download <id> [-o dir]` | 是 | 按附件 ID 下载 |
| `multica attachment upload` | 是 | 上传并挂到 chat 回复 |
| **`multica attachment delete` / `revoke` / `update`** | **不存在** | 附件命名空间下**没有**删除或撤回子命令 |
| `multica issue comment delete <comment-id>` | **是** | 帮助原文：*"Delete a single comment. Its replies are kept: a comment that has replies stays in the thread as an empty placeholder (deleted_at set) so they keep their place."* |
| `multica issue comment update` | 是 | 编辑评论 |
| `multica issue comment resolve` / `unresolve` | 是 | 线程解决状态 |

### 1.1 对旧断言的纠正

Q0 上一版写「**平台评论附件不可删除**」。本轮核实结论：

- **该断言既未被证实，也未被证伪。** 证据只到命令面这一层。
- CLI **确实存在**一条可用管控途径：`issue comment delete`（删除承载评论）。
- 但该命令的帮助文本**完全没有提到附件**：既没说附件随之清除，也没说保留。
- 因此**未验证**的两点是：① 评论被删除后附件 blob 是否被清除；② `static.multica.ai` 上的直链是否随之失效。

**结论写法**：*"CLI 暴露 `issue comment delete` 这一条评论级管控途径；附件 blob 的生命周期未在 CLI 契约中声明，需平台 owner 确认，不能由本轮推断。"*
